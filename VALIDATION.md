# Проверки GDWorld Android

Дата: 22 ноября 2026.

## Рабочая версия 0.1.6 — передача файлов для диагностики

- Перед изменением проверен единственный вызов FileItemLayout, существующий utils.file.shareFile и manifest/provider_paths. Новая команда только для обычных файлов, использует штатный ACTION_SEND + content URI + FLAG_GRANT_READ_URI_PERMISSION. Выбор получателя остаётся в системном окне Android. Исключения подготовки Intent передаются в штатный обработчик ошибок.
- generic_share уже существовал на английском/русском; добавлены украинский, белорусский и польский варианты. Новых зависимостей и разрешений не добавлено.
- Корень встроенного менеджера уже .minecraft; внутри нужен путь versions/GDWorld-1.21.1-21.1.267. Системный FolderProvider опубликован как GDWorld и показывает android_data/files/.minecraft. Это другой путь навигации, не отсутствие каталога игры.
- После сообщения владельца об отсутствии отчёта на OnePlus задан стандартный ErrorFile в существующем DIR_NATIVE_LOGS: files/logs/native/hs_err_pid%p.log. Пользовательская настройка ErrorFile не переопределяется. JVM21 на хосте приняла опцию с пробелами в пути и сохранила %p в PrintFlagsFinal; это проверка синтаксиса, не воспроизведение нативного Android-падения.
- Новый APK/окно отправки пока не проверены на телефоне. Передача отчёта не является исправлением нативного падения JVM; исследование требует исходного hs_err_pid*.log.

## Исправления 0.1.4 — вложенные разделы и авторизация

- ADB-снимок подтвердил Invalid signature for profile public key; журнал сервера показал подпись длиной 1 байт вместо 384. Это соответствует AA== в [ProfileKeyFilter authlib-injector](https://github.com/yushijinhun/authlib-injector/blob/develop/src/main/java/moe/yushi/authlibinjector/httpd/ProfileKeyFilter.java). GDWorld-мост объявляет feature.enable_profile_key; POST /minecraftservices/player/certificates возвращает 204 для ожидаемого Bearer, 401 для чужого. Authlib 6.0.54 с телефона возвращает null для успешного пустого ответа (проверено по байткоду). Серверные online-mode/enforce-secure-profile не изменялись.
- AuthLimiter Gravit (3/8000 ms) выдавал auth.trylater при серии полных входов. Вместо повторного auth используется restore, refresh только после auth.expiretoken. Read/restore/write сериализован монитором GdSession; UUID ответа проверяется, повернутый refresh сохраняется даже при следующем сетевом сбое. Сообщение ограничителя переведено на пять языков.
- Регистрация разрешённого Android SHA задаёт CLIENT, как настольный LauncherResponse; isAuth и UUID не назначаются. Изолированная проверка на библиотеках Gravit 5.7.14 прошла: отсутствие/неизвестный/неверный хеш и регистрация после входа запрещены. Модуль обновлён; перезапущен только Gravit, игровой порт 25566 оставался доступен.
- Полный JVM-набор: 37 тестов, 34 успешных, 3 ручные сетевые проверки пропущены. Пять новых тестов: повторный restore без auth/refresh, refresh после истечения, отсутствие повторов при ошибке токена/сети, отказ смене UUID, сохранение нового refresh после обрыва. org.json добавлен только для JVM-тестов вместо Android-заглушек.
- Файловая панель на узком экране стала накладной, команды переносятся. Панели аккаунтов располагаются вертикально, действия карточки ниже имени. Размеры файлов форматируются с аргументами. «О лаунчере» использует стандартный компактный диалог с корректными названиями исходных проектов. По просьбе владельца добавлены Best_Jaro и Endayt на пяти языках.
- Вход 0.1.4 подтверждён пользователем и записью игрового сервера. Файловый менеджер и диалог авторства проверены по ADB-снимкам; обнаруженное падение аккаунтов исправлено и проверено на Poco в 0.1.5. ## Исправления 0.1.3 — интерфейс расширенных возможностей

- Через ADB на Poco X3 Pro (`M2102J20SG`, Android API 31) воспроизведена исходная проблема. Физический экран 1080×2400, плотность 440 dpi, ширина окна 392 dp; `DisplayCutout` требует верхний отступ 91 px.
- Весь расширенный интерфейс использует safeDrawingPadding/imePadding. Верхняя панель на узком окне разделена на заголовок и прокручиваемые действия, заголовок ограничен своей шириной. В широком окне действия занимают не более 60% ширины, оставляя место навигации. Кнопки имеют высоту не менее 48 dp.
- Стрелка на главной расширенного меню вызывает возврат в GDWorld, во вложенных разделах использует штатный back dispatcher; домашняя кнопка расширенной навигации сохранена. Подпись возврата локализована на пяти языках.
- При ширине менее 600 dp домашний экран расширенного меню использует LazyColumn: аккаунт/запуск, быстрые команды и полноширинные карточки с ограниченной высотой. Настроенный контент домашней страницы сохранён; его внутренняя прокрутка ограничена 400 dp, чтобы избежать бесконечных ограничений вложенного LazyColumn.
- После ручного обновления на Poco подтверждены versionName 0.1.3 / versionCode 4. Снимки через ADB проверены сверху и после прокрутки: нормальная ширина карточек, читаемый журнал/список изменений, шапка ниже камеры. UI-дерево показывает область кнопки назад [22,91]–[154,223]: ниже выреза и не менее 48 dp. Владелец вручную подтвердил возврат в GDWorld, повторный вход и прокрутку до нижних карточек. MIUI запрещает ADB-инъекцию нажатий (INJECT_EVENTS), поэтому нажатия не выдаются за автоматические тесты. Установка по USB не выполнялась.

## Исправления 0.1.2

- Найдена гонка в JvmService: callback выхода JVM ставил отправку UDP-результата в корутину; ZLNativeInvoker.jvmExit сразу после callback завершает процесс. Приёмник в старом коде также привязывался к порту после запуска сервиса. Это позволяло потерять единственный результат и ждать бесконечно.
- Новый JvmExitSignal привязывает сокет синхронно до старта JVM. Результат отправляется синхронно перед завершением дочернего процесса, без глобального старого receiveMsg и без подмены неизвестного кода успехом. Некорректные пакеты отклоняются, ожидание поддерживает отмену, контролирует исчезновение процесса и ограничено по времени. Операции с единственным JVM-сервисом сериализованы.
- Вместо ожидания исчезновения всех дочерних процессов завершается только собственный :jvm; :game не затрагивается. Очистка принадлежит ожидающей корутине в finally. Тайм-аут преобразуется в обычную ошибку установки, чтобы TaskFlowExecutor не поглотил его как пользовательскую отмену.
- Java выбирается из javaVersion.majorVersion Minecraft, с совместимым встроенным runtime; для 1.21.1 сразу Java 21. Повторные попытки поддерживают 8 → 17 → 21 → 25. Номер процессора и фактический runtime отображаются вместо пустого Installing in the foreground; процент обновляется после проверки результатов процессора.
- Горизонтальная компоновка: отдельные панели запуска/управления и входа/прогресса; каждая прокручивается независимо. Операция подготовки хранится выше ветвей ориентации.
- Полный локальный JVM-набор: **32 проверки, 29 выполнены успешно, 3 ручные сетевые проверки пропущены**. Новые: 5 реальных loopback UDP-тестов (быстрый выход, отсутствие старого успеха, неверный пакет/длинный следующий код, освобождение порта, занятый порт) и 4 теста выбора Java по метаданным. Kotlin/Java приложения скомпилированы.
- Эти тесты не являются проверкой NeoForge на физическом телефоне. Реальная установка, горизонтальная UI с клавиатурой и игровой запуск на Android ещё требуют проверки устройством.
